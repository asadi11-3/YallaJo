================================================================================
YallaJoJo AUTH DATABASE & MIGRATION DEEP EXPLORATION REPORT
================================================================================

EXECUTIVE SUMMARY
=================
This report provides comprehensive analysis of all database tables, migrations, 
entity configurations, and relationships related to Authentication in YallaJoJo.

The Auth system is split across two modules:
1. Security Module (Security.Infrastructure) - User identity and role management
2. Auth Module (Auth.Infrastructure) - Session, device, refresh token, OTP management

================================================================================
1. DATABASE SCHEMA OVERVIEW
================================================================================

Schema Distribution:
- Security Schema: User identity, roles, claims, emails, phones, audit logs
- Auth Schema: Sessions, devices, refresh tokens, OTPs, external providers

Database Context Files:
- Security.Infrastructure.Persistence.SecurityDbContext
- Auth.Infrastructure.Persistence.AuthDbContext

================================================================================
2. SECURITY MODULE TABLES
================================================================================

2.1 USERS TABLE
Schema: security | Table: Users

Columns:
- Id (uniqueidentifier, PK, ValueGeneratedNever)
- IsActive (bit, Default: 0)
- PasswordHash (nvarchar(512), Required)
- CreatedAt (datetime2, Required)
- UpdatedAt (datetime2, Nullable)
- IsDeleted (bit, Default: 0)
- DeletedAt (datetime2, Nullable)
- RowVersion (rowversion, Concurrency Token)

Indexes:
- IX_Users_IsActive
- IX_Users_IsDeleted

Key Features:
✅ Soft delete support with query filter
✅ Concurrency control via RowVersion
✅ Audit trail (CreatedAt, UpdatedAt, DeletedAt)
✅ Password hash stored (max 512 chars)
⚠️ No unique constraint on email (enforced at Emails table level)

Relationships:
- One-to-Many with Emails (Cascade Delete)
- One-to-Many with Phones (Cascade Delete)
- One-to-Many with UserRoles (Cascade Delete)
- One-to-Many with UserClaims (Cascade Delete)

- CreatedAt (datetime2, Required)
- UpdatedAt (datetime2, Nullable)
- IsDeleted (bit, Default: 0)
- DeletedAt (datetime2, Nullable)
- RowVersion (rowversion, Concurrency Token)

Indexes:
- IX_Devices_DeviceToken (UNIQUE)
- IX_Devices_UserId
- IX_Devices_IsTrusted

Key Features:
✅ UNIQUE constraint on DeviceToken
✅ Device trust tracking with timestamp
✅ Last activity tracking
✅ Soft delete support
✅ Concurrency control
⚠️ Logical FK to Users (no database constraint)

Relationships:
- One-to-Many with Sessions (Cascade Delete)
