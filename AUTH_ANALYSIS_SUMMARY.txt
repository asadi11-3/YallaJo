================================================================================
YALLAJO AUTH MODULE - DEEP EXPLORATION REPORT
================================================================================

ARCHITECTURE OVERVIEW
================================================================================

The Auth module follows Clean Architecture with CQRS pattern:
- Auth.Domain: Entities, value objects, domain events, repository interfaces
- Auth.Application: Commands, queries, handlers, application services
- Auth.Infrastructure: EF Core, repositories, services, event handlers
- Auth.Presentation: API endpoints, rate limiting, request/response models
- Auth.Contracts: Integration events for cross-module communication

DOMAIN LAYER ENTITIES
================================================================================

1. SESSION (Aggregate Root)
   - UserId, DeviceId, ExpiresAt, IsRevoked, RevokedAt, IpAddress
   - Methods: Create(), Revoke()
   - Events: UserLoggedInEvent, SessionRevokedEvent
   - Lifetime: 30 days

2. REFRESH TOKEN (Aggregate Root)
   - UserId, SessionId, TokenHash (SHA256), ExpiresAt, IsRevoked, ReplacedByTokenId
   - Methods: Create(), Revoke(replacedByTokenId)
   - Storage: Only hash stored in DB, plaintext returned to client
   - Lifetime: 30 days
   - Rotation: Old token revoked, new token issued

3. DEVICE (Aggregate Root)
   - UserId, DeviceToken (UUIDv7), UserAgent, DeviceName, IsTrusted, TrustedAt, LastSeenAt
   - Methods: Create(), Trust(), RecordSeen()
   - Purpose: Track user devices, enable device trust workflows

4. OTP (Entity)
   - UserId, Purpose (EmailVerification/PasswordReset), CodeHash (PBKDF2), DeliveryChannel, DeliveryAddress
   - ExpiresAt, AttemptCount, IsUsed, UsedAt
   - Methods: Create(), IncrementAttempt(), MarkUsed()
   - Invariants: Max 5 attempts, 10-minute expiry
   - Storage: Only hash stored in DB

5. EXTERNAL PROVIDER (Aggregate Root)
   - UserId, Provider (normalized), ProviderUserId, ProviderEmail, IsActive, VerifiedAt
   - Methods: Create(), Deactivate()
   - Purpose: OAuth provider linking/unlinking
   - Constraint: Unique (Provider, ProviderUserId) where IsActive = 1

APPLICATION LAYER - COMMANDS
================================================================================

LOGIN COMMAND
  Input: Email, Password
  Output: UserId, AccessToken, RefreshToken, RefreshTokenExpiresAt
  Flow:
    1. Verify credentials via Security module
    2. Check email verified
    3. Create Device (UUIDv7 token)
    4. Create Session (30-day expiry)
    5. Generate refresh token (64 random bytes)
    6. Hash refresh token (SHA256)
    7. Create RefreshToken entity
    8. SaveChanges (dispatch events)
    9. Generate JWT AccessToken with claims: sub, email, jti, iat, sid, role, custom
  Security: Email verification mandatory, IP address captured

REFRESH TOKEN COMMAND
  Input: RefreshToken (plaintext)
  Output: AccessToken, RefreshToken, RefreshTokenExpiresAt
  Flow:
    1. Hash provided token
    2. Fetch token from DB (intentionally without IsRevoked filter)
    3. Detect reuse attack: if revoked, revoke entire session
    4. Check expiration
    5. Validate session
    6. Validate user
    7. Generate new token
    8. Revoke old token with ReplacedByTokenId
    9. Update device LastSeenAt
    10. Generate new JWT
  Security: Token rotation, reuse-attack detection, session validation

LOGOUT COMMAND
  Input: RefreshToken
  Output: Success
  Flow:
    1. Hash token
    2. Fetch token
    3. Revoke token and session
    4. Invalidate cache
  Security: Idempotent, revokes both token and session

LOGOUT ALL COMMAND
  Input: (none, uses current user)
  Output: Success
  Flow:
    1. Fetch all active sessions for user
    2. Fetch all active refresh tokens for user
    3. Revoke all
    4. Invalidate cache
  Security: Requires authentication

VERIFY EMAIL COMMAND
  Input: Email, OtpCode (6-digit)
  Output: UserId, AccessToken, RefreshToken, RefreshTokenExpiresAt
  Flow:
    1. Get user ID
    2. Fetch OTP
    3. Check exhausted (5+ attempts)
    4. Check expired (10 minutes)
    5. Increment attempt
    6. Verify OTP code
    7. Create Device and Session
    8. Generate RefreshToken
    9. Mark OTP used
    10. Mark email verified in Security module
    11. Generate JWT
  Security: Attempt limiting, expiry checking, one-time use

FORGOT PASSWORD COMMAND
  Input: Email
  Output: Generic success message
  Flow:
    1. Get user ID (or return generic message if not found)
    2. Generate 6-digit OTP
    3. Hash OTP
    4. Create OTP entity
    5. Send email
  Security: User enumeration prevention, email failure doesn't fail command

RESET PASSWORD COMMAND
  Input: Email, OtpCode, NewPassword, ConfirmNewPassword
  Output: Success
  Flow:
    1. Get user ID
    2. Fetch OTP
    3. Verify OTP
    4. Reset password via Security module
    5. Mark OTP used
    6. Revoke all sessions/tokens (automatic via event handler)
  Security: OTP validation, password complexity delegated to Security module

RESEND OTP COMMAND
  Input: Email, Purpose (EmailVerification/PasswordReset)
  Output: Generic success message
  Flow:
    1. Get user ID
    2. Check rate limit: 1-minute cooldown
    3. Mark old OTPs as used
    4. Generate new OTP
    5. Send email
  Security: Rate limiting, OTP invalidation, user enumeration prevention

REVOKE SESSION COMMAND
  Input: SessionId
  Output: Success
  Flow:
    1. Check authentication
    2. Fetch session
    3. Verify ownership (session.UserId == currentUser.UserId)
    4. Revoke session and all its tokens
    5. Invalidate cache
  Security: Users can only revoke their own sessions

TRUST DEVICE COMMAND
  Input: DeviceId
  Output: Success
  Flow:
    1. Check authentication
    2. Fetch device
    3. Verify ownership
    4. Mark as trusted
  Security: Users can only trust their own devices

LINK EXTERNAL PROVIDER COMMAND
  Input: Provider, ProviderUserId, ProviderEmail
  Output: ProviderId
  Flow:
    1. Check authentication
    2. Verify user doesn't already have active link for this provider
    3. Verify provider account isn't already linked to another user
    4. Create ExternalProvider entity
  Security: Prevents duplicate links, prevents provider account hijacking

UNLINK EXTERNAL PROVIDER COMMAND
  Input: ExternalProviderId
  Output: Success
  Flow:
    1. Check authentication
    2. Fetch provider
    3. Verify ownership
    4. Deactivate (soft delete)
  Security: Users can only unlink their own providers, soft deactivation allows re-linking

FORCE REVOKE USER SESSIONS COMMAND
  Input: UserId
  Output: Success
  Flow:
    1. Fetch all active sessions for target user
    2. Fetch all active tokens
    3. Revoke all
    4. Invalidate cache
  Security: Admin-only (MustHavePermission(User, UpdateAny))

APPLICATION LAYER - QUERIES
================================================================================

LIST ACTIVE SESSIONS QUERY
  Input: UserId
  Output: IReadOnlyList<ActiveSessionListItemDto>
  DTO: SessionId, DeviceId, DeviceName, UserAgent, IpAddress, CreatedAt, ExpiresAt
  Flow:
    1. Fetch non-revoked, non-expired sessions
    2. Fetch associated devices
    3. Project to DTOs
  Caching: 5 minutes per user, tag-based invalidation
  Note: DTO doesn't include IsCurrent (computed in endpoint from JWT sid claim)

INFRASTRUCTURE LAYER - SERVICES
================================================================================

JWT TOKEN SERVICE
  - Algorithm: HMAC-SHA256
  - Access Token Lifetime: 15 minutes (configurable)
  - Refresh Token: 64 random bytes (512 bits), base64 encoded
  - Claims: sub, email, jti, iat, sid, role, custom
  - Refresh Token Hashing: SHA256

OTP SERVICE
  - Generation: 6-digit random (000000-999999)
  - Hashing: ASP.NET Core PasswordHasher (PBKDF2)
  - Verification: Supports rehashing

GMAIL EMAIL SERVICE
  - SMTP: smtp.gmail.com:587 with TLS
  - Authentication: App-specific password
  - Logging: Email sending logged for audit trail
  - Resilience: Failures logged but don't fail command
