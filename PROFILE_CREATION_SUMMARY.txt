ISSUE: GetYourProfile returns 404 after user registration

ROOT CAUSE: Timing/Race Condition
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The profile creation flow is ARCHITECTURALLY SOUND but has a TIMING VULNERABILITY:

1. User registers → Security.UserRegistrationService creates User aggregate
2. User.Register() raises UserCreatedEvent (domain event)
3. UserCreatedDomainEventHandler converts to UserCreatedIntegrationEvent
4. Event is written to OutboxMessages table (NOT immediately published)
5. Registration returns 201 Created with UserId
6. Client receives JWT and calls GET /profile IMMEDIATELY
7. ❌ Profile doesn't exist yet (404) — OutboxMessage still pending!
8. 10 seconds later: CompositeOutboxProcessor runs
9. OutboxProcessor publishes IntegrationEventNotification via MediatR
10. UserCreatedIntegrationEventHandler creates Profile in Accounts DB
11. ✅ Subsequent GET /profile calls return 200 OK
