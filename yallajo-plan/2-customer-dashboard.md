# Area 2 — Customer / Tourist Dashboard

> **Actor:** Customer / Tourist (authenticated)
> **Plan section:** §3 of `yallajo-dashboard-ui-ux-plan.md`
> **Namespaces:** `accounts`, `booking/my-*`, `booking/join-requests`, `social`,
> `analytics/recommendations`, `payments/my-*`, `invoices/my-*`, `disputes/my`,
> `support`, `notifications`, `devices`.
> Status legend: ✅ Wire · ♻️ Repurpose · ⏭️ Skip · 🟥 USER builds.
> **Architecture & rules:** see [`0-architecture-and-rules.md`](0-architecture-and-rules.md). **Code area `Accounts`** (`/accounts/*`); every page is `NoStore` (`UI-PERF-C2`).
> **Permissions (verified against shipped `Areas/Accounts/Controllers/*`):** every controller is `[Authorize]` **plus** most read/write actions carry a granular **`[RequirePermission(WebPermission.{Feature}.{Action})]`** — Accounts is **not** bare `[Authorize]`. Real constants in use: `Payment.Read`/`Create`, `Invoice.Read`/`Download`, `BookingDispute.Create`, `Refund.Read`/`Create`, `Review.Read`/`Update`/`Delete`, `AccessibilityReview.Read`/`Delete`, `Recommendation.Read`, `Preference.Read`/`Update`, `Interaction.Create`, `Notification.Read`/`Delete`, `SupportTicket.Read`/`Close`, `DeviceToken.Create`/`Delete`. (Pages still `[Authorize]`-only — no `[RequirePermission]`: Overview, My Trips list/cancel, Wishlist, Profile, Delete, ChangePassword, UpdatePhone, Settings notifications/marketing/sessions/logout-all.) The API additionally enforces per-user ownership.
> **BFF routes vs API routes (read this).** Every `/social/*`, `/payments/*`, `/invoices/*`, `/notifications/*`, `/analytics/*`, `/auth/*` route shown below is the **API-layer** path the `ApiClient` calls. The **button/form the browser POSTs to is the page-scoped BFF route** (`[HttpPost]` + anti-forgery + PRG), verified against the shipped controllers — e.g. `POST /accounts/wishlist/remove/{entityType}/{entityId}` (not `DELETE /social/favorites/...`), `POST /accounts/reviews/edit` (not `PUT /social/reviews/{id}`), `POST /accounts/bookings/{id}/pay` (not `POST /payments/initiate`). The API `PUT`/`DELETE`/`PATCH` verbs are valid only at the ApiClient→API layer.

## Shared shell
Top bar: global search · language switcher · notification bell (`GET /notifications/unread-count` `AJAX⟳`, SignalR push) · avatar menu (`GET /accounts/profile`). Nav driver: `GET /security/me`. Bell badge is `aria-live="polite"` with the `NF7` shake suppressed under reduced motion (`A11Y9`/`M3`) — applies to **every** page in this area, not just Overview.

Approve/reject live in the Guide area (§5.10).
- **Buttons:** **Book Again / New Booking** → tour-booking checkout (→ §3.7 pay) · **Cancel Booking** → `POST /accounts/bookings/{id}/cancel` (inline) · **Request to Join** → `POST /accounts/join-requests` (`JoinRequest.Create`) · booking row → §3.3 (nav).

### 3.3 Booking Detail
`GET /booking/{id}` *(owner/provider/admin scoped)* · `GET /invoices/my-invoices?bookingId` · `/invoices/{id}/download` · `POST /booking/{id}/dispute` (Completed only) · `/booking/{id}/cancel` · weather widget.
- **Buttons** *(BFF routes on the booking; `/social|invoices|booking/*` shown are the API binding)*: **Download Invoice** → `GET /accounts/invoices/{id}/download` · **Raise Dispute** → `POST /accounts/bookings/{id}/dispute` (Completed only; `BookingDispute.Create`) · **Cancel Booking** → `POST /accounts/bookings/{id}/cancel` (inline) · **Pay Now** → `POST /accounts/bookings/{id}/pay` (`Payment.Create`) · **View Tour** → §2.5 (nav).
- **Stack:** **Area** `Accounts` · **Route** `/accounts/bookings/{id}` · **Cache** `NoStore` · **Perm** `[Authorize]` (owner/provider/admin scoped by API) · **Rules** `R2` · `PRINT1`/`PRINT2` invoice PDF (QuestPDF) · `PRINT3` .ics export · `F8` cancel/dispute confirm · weather widget (§0.2) · `REV1` `?action=review` modal · staleness via `UpdatedAt` (the booking-detail wire contract `TourBookingDetailResponse` exposes **`UpdatedAt`, not a `RowVersion` token** — no `ST1` optimistic-concurrency round-trip on cancel/dispute; the API guards state preconditions server-side).
> **Two distinct dispute objects:** the **Raise Dispute** here is `POST /booking/{id}/dispute` (`OpenBookingDisputeCommand(BookingId, Reason)`, Completed + 48h window), surfaced as `TourBookingDisputeResponse` **inside this booking**. The §3.8 Disputes page is a **separate, payment-scoped** object (`POST /disputes` → `OpenDisputeApiRequest(PaymentId, Reason, Description)`, listed by `GET /disputes/my`). A booking dispute does **not** appear in `/disputes/my`.

### 3.7 Payments & Invoices — TWO shipped surfaces (no `/accounts/billing`)
> There is **no `/accounts/billing` route**. Payments and invoices are separate shipped controllers, and **Pay Now lives on the booking**, not a billing page.

**§3.7a Payments** *(shipped `PaymentsController`)* — BFF `GET /accounts/payments` (`Payment.Read`). API binding: `GET /payments/my-payments`, `/payments/{id}`.
**§3.7b Invoices** *(shipped `InvoicesController`)* — BFF `GET /accounts/invoices` (`Invoice.Read`) · `GET /accounts/invoices/{id}/download` (`Invoice.Download`). API binding: `GET /invoices/my-invoices`, `/invoices/{id}[/download]`.
**Pay** — **`POST /accounts/bookings/{id}/pay`** (`BookingsController`, `Payment.Create`; API `POST /payments/initiate`). *(Dev-only API `POST /payments/{bookingId}/simulate-success` — never in prod UI.)*
- **Buttons:** **Pay Now** → `POST /accounts/bookings/{id}/pay` (→ gateway → §3.3) · **Download Invoice** → `GET /accounts/invoices/{id}/download` · payment/invoice row → §3.3 (nav).
- **Stack:** **Area** `Accounts` · **Route** `/accounts/payments` · `/accounts/invoices` · **Cache** `NoStore` · **Perm** `[Authorize]` + `WebPermission.Payment.Read` (payments) / `Invoice.Read`+`Download` (invoices) / `Payment.Create` (pay action) (shipped) · **Rules** `R2` · `PAY1` PSP iframe (never store/log card) · `PAY2` idempotency key + disable Pay · `PAY3` exact total+currency+refund+lock countdown (`CAL4`) · `PAY4` webhook server-confirm ("Processing…") · `PRINT2` invoice PDF · DEV-only `simulate-success` never rendered in prod.
